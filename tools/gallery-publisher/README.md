# Hyper Gallery 本地发布工具

## 打开

在网站源码文件夹中，双击根目录的 **「打开 Gallery 发布工具.command」**。它会打开本地网页：<http://127.0.0.1:8768/>。终端窗口保持开启，关闭终端或按 Control+C 停止工具。

如果双击没有运行，也可以在网站源码目录执行：

```bash
python3 tools/gallery-publisher/publisher.py
```

这台 Mac 已有运行所需环境。换到新电脑时需要 Python 3 和 Node.js 24，并在网站源码目录先安装依赖：

```bash
npm ci
npm ci --prefix gallery/site
```

## 发布新一期

1. 把命名好的原图放在同一个文件夹，支持 JPG / JPEG / PNG / WebP / TIFF / HEIC / HEIF。照片直接放在该文件夹内，不需要自己生成缩略图。
2. 点击「选择文件夹」，或粘贴完整路径并点击「读取」。文件夹名称会作为网站中的专辑目录名；类似 `2026-10-23-iPhoneDuo` 的日期前缀会自动填写拍摄日期。
3. 填专辑标题、日期、分类。默认选第一张作封面，可以改选。
4. 默认每张照片都**不生成 `featured` 字段**。勾选某张照片的「首页精选」，才会写入 `featured: true`。精选数量不限。
5. 专辑描述和每张照片描述默认都是 `description: ""`，可以一直留空。用箭头调整照片顺序。
6. 点击「生成配置文件」，工具把 `index.md` 保存到**所选原图文件夹**，不会改写原图。展开「查看即将保存的 index.md」可以检查配置。
7. 填写完成后点击「发布到 Gallery」。表单中未保存的修改会先自动保存，然后整辑原图和 `index.md` 一次提交到 `Hyper-jiawei/Hyper-jiawei.github.io` 的 `main` 分支、`gallery/content/<专辑目录>/`。
8. 提交成功后，点击「查看部署进度」。GitHub Actions 变绿后网站更新，工具不会在本机提前生成或上传大批 WebP 衍生图。

生成配置只是本地保存；**只有点击发布才上传到 GitHub**。网站源代码、其他专辑和原图文件不会被本地工具改动。原图在公开仓库发布后可公开访问。

## 已经有 index.md

读取文件夹时会带入现有标题、日期、文案、封面和精选设置。如果之前使用 `featured: 1` 等数字，会显示为已勾选精选，生成新配置时统一写成 `featured: true`。

也可以先生成配置，再用自己的编辑器填写 `index.md`。回到工具点击「重新读取配置」即可；如果外部编辑器修改了文件而表单也有未保存修改，工具会阻止覆盖，先重新读取后再编辑。

文件名必须与配置中的 `src` 完全一致，包括空格、扩展名和大小写。工具会报告不匹配的文件。不要使用同名的 JPG 和 HEIC；它们会形成重复照片标题。

## 更新已经发布的同一期

选择完整的专辑文件夹，目录名保持原样，勾选 **「更新同名专辑」** 后再发布。未勾选时不覆盖已存在的专辑。

更新时将同步这一辑的原图和配置：本地已删除的顶层照片会从同名远端专辑中移除；其他专辑、博客文章、同目录额外文档和子文件夹不会被删除。删除也只体现在新的 Git 提交中，历史版本仍可恢复。

原图字节相同的文件会跳过上传。完全相同的专辑不会重复创建提交。远端同时有人提交时，工具会停止更新分支，让你重试，始终不会强制推送。

## GitHub 登录

打开「GitHub 连接」并点击「连接 GitHub」。工具依次尝试：

1. `GITHUB_TOKEN` / `GH_TOKEN` 环境变量。
2. GitHub CLI 已有登录。
3. 本机 Git 凭据管理器（这台 Mac 使用钥匙串）。

如果没有可用登录，在连接栏填写 GitHub 的访问令牌：目标仓库选 `Hyper-jiawei.github.io`，仓库权限需要 **Contents: Read and write**。不要把令牌写进 `index.md`。

连接栏的令牌仅保存在本次服务进程内存中，不写入配置、照片、网站源码或浏览器存储；重启后可重新复用本机登录或填写令牌。

## 常见问题

- **发布成功，但网页没变**：提交和网站部署是两步。打开返回的 Actions 链接，等部署成功。失败时原网站保持可用。
- **网页提示文件太大**：网页上传单文件限制为 25 MiB；普通 Git 仓库的单文件限制为 100 MiB。工具按原图逐个上传，不走网页上传表单。整辑合计超过 25 MiB 不代表某张照片超限。工具会在上传失败时指出文件名和大小，100 MiB 以上的单个文件需要另行处理。
- **每次提交耗时随图片增加**：当前工作流仍会处理整站照片。本地发布工具只减少人工上传步骤；Actions 图片缓存是另一项优化。
- **改了源文件后报错**：发布时请暂停修改照片和配置。工具会检查文件内容是否在上传期间变化。
- **网络中断**：原图先上传为 Git 对象，全部完成后才更新分支，不会发布半辑。最终提交阶段断线时，先查看 GitHub 提交记录，再决定是否重试。
- **Mac 文件夹选择被取消**：可以重新选择，也可以粘贴路径。路径里可以有中文和空格。
- **端口被占用**：重新打开同一工具会复用已运行服务；也可用 `python3 tools/gallery-publisher/publisher.py --port 8769` 换一个端口。
- **本地网站 checkout 没有新增照片**：发布通过 GitHub API 完成，原图保留在所选文件夹；之后需要本地网站源码时正常 `git pull` 即可。

## 开发验证

```bash
python3 -m unittest discover -s tools/gallery-publisher/tests -v
```

测试使用临时文件和模拟 GitHub，不上传照片。服务仅监听 `127.0.0.1`，所有文件操作和发布接口都要求本地会话标识，其他网页不能直接触发发布。

## 自动分仓存储

发布前按原图三倍开销估算主站容量，采用 650 MiB 保守预算。超过预算或专辑已分仓时，使用 `gallery01`、`gallery02` 等私人仓库保存未改写原图和完整配置；每个原图库按 800 MiB 预算轮换。跳过同名公开仓库，不改变其可见性。单辑超过 800 MiB 需拆辑。仓库大小统计有延迟，这些是工具预算，并非 GitHub 硬容量限制。

主站保留展示配置副本、EXIF / 色块清单及最长边不超过 3000px 的 WebP。分仓专辑在本机生成预览，Actions 直接复制，无需私人仓库令牌，也不再重复转换这些原图。已有普通专辑仍按原流程构建。

**私人原图下载需要登录有权限的 GitHub 账号**，匿名访客只能看公开预览。不会向网页写入令牌。已有公开原图不会自动迁移或变为私密。原图库先完成提交，主站最后更新；中途失败可重试。

凭据需有创建和读写私人仓库的权限。仅授权主站的细粒度令牌可能需重新授权；权限不足时停止，不回退为公开仓库。公开预览也接近主站预算时将停止并提示接入图片托管，拆分私人原图不能无限扩容 Pages。

更新后请关闭旧工具终端，再双击启动文件以加载新版本。
