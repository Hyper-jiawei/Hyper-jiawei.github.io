# 网站性能检查（2026-10-18）

本次以当前 Astro 网站及工作区已有改动为基线，要求保留现有视觉、图片质量、布局、交互和动效。检查范围包括构建产物、图片、字体、模块依赖、懒加载、导航预取、列表缓存、滚动与 resize 处理、灯箱和静态缓存配置。

## 已修复：照片页预加载无关的动态模块

`scripts/module-preloads.mjs` 原先在遇到 `data-gallery` 时遍历所有动态依赖，导致节日图案、头像配饰、彩蛋页和点击动画也被写入预加载提示，失去了按需加载的意义。

现按入口源码识别灯箱和 PhotoSwipe 核心，只预加载它们及其静态依赖。运行时入口、事件处理、CSS、动画参数和图片资源均未修改。节日图案和头像仍由原有条件正常加载，点击动画和彩蛋页仍由原有交互触发。

本地 Chromium、全新浏览器上下文、普通日期（模拟北京时间 2026-10-17）、`/nwpu-postcards/` 的实测：

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| HTML 模块预加载提示 | 8 | 4 |
| 首次加载 JavaScript 请求 | 11 | 8 |
| JavaScript 解压后字节数 | 204,490 | 143,003 |

减少 61,487 字节，约 30.1%。这是本地资源加载量，不是线上压缩传输量或 Core Web Vitals 的改善幅度。节日当天需要正常加载节日图案，因此节省量会相应变小。

## 后续修复：彩蛋页在慢网络下跳过入场爆炸

后续复现发现，彩蛋页的 6 秒安全超时会先解除等待状态，而入场爆炸依赖主模块初始化；当模块下载超过 6 秒时，初始化检查不到等待状态，整段效果被跳过。这是前述检查未覆盖到的慢网络时序。

入场效果现迁移至仅彩蛋页包含的内联脚本，在 body 开始处独立运行。主模块不再负责启动它，因此不依赖路由器、主模块或彩蛋交互模块下载。保持原有 26 条彩带、22 片纸屑、配色、轨迹、1500ms 爆炸和后续页面揭示时长；没有修改 CSS。直接访问不播放，减少动态效果偏好仍被尊重，导航离开时清理效果。

修复后 27 项测试和生产构建通过。浏览器验证中英日页面在外部 JavaScript 阻塞超过 6 秒时，均在模块就绪前完整播放一次；外部模块全部加载失败时也正常播放并显示页面。另验证直接访问、减少动态效果，以及离开页面时的清理。全部 5 个构建 CSS 文件仍与原基线逐字节一致。
